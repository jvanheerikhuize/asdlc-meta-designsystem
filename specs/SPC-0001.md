# SPC-0001 · Design token foundation and foundational Atoms skeleton

Tier: **skeleton** · Readiness: **100%**

Establish the end-to-end walking skeleton of the design system: the unidirectional six-tier architecture, the Lumen-inspired dual-theme design token set, foundational interactive Atoms, the live Showcase site published alongside the specification dashboard, and the agent-consultable design catalog for cross-repository use.

## Non-goals

- Complex multi-column page templates, routing, or data-fetching logic.
- Third-party framework wrappers or build-time utility class generation.

## Requirements

### REQ-0001 · Components are organized into six unidirectional tiers with strict composition (active)

Every design system artifact MUST belong to one of six hierarchical tiers — Tokens, Atoms, Molecules, Organisms, Templates, or Pages. Dependencies MUST flow strictly downward (a lower tier MUST NOT import or depend on any higher tier), every Molecule MUST compose one to three kinds of Atom, every Organism MUST compose lower-tier components, Templates MUST NOT contain or name any component, Pages MUST live outside the shared package, and Molecules and Organisms MUST compose Atom controls and foundational surface Atoms instead of re-implementing raw form/button controls or duplicate container chrome.

**REQ-0001#1**

```gherkin
Given a Molecule composed of Atom controls and design tokens
When the dependency direction and composition graph are inspected
Then the Molecule imports and composes at least one Atom, depends only on Atoms and tokens, and no Atom depends on any higher tier
```

**REQ-0001#2**

```gherkin
Given the shared package
When its contents are inspected
Then it contains no Page, and every Template exposes only slots
```

Because:
- FCT-0001 (active): Atomic Design organizes interfaces into five strictly layered compositional tiers
- FCT-0010 (active): The design system uses six tiers with tokens as the first and Pages outside the shared package

### REQ-0002 · Visual token foundation provides Lumen-inspired dark surfaces, typography, spacing, and reduced-motion rules (active)

The system MUST expose semantic design tokens for canvas, elevated surfaces, translucent hairline borders, foreground text hierarchy, brand and status accents, spacing, radii, typography scales, control and panel sizes, stacking layers, and motion durations — shipping a Lumen-inspired dark-first default preset and an explicit light-theme preset — with reduced-motion fallbacks and readable contrast ratios across all interactive surfaces. Raw colors MUST be named as primitives that only semantic tokens use. Components MUST take every color, length, weight, layer and duration from semantic tokens. The vocabulary MUST also cover status states, data series, code, gradients, text styles, aspect ratios, interaction and safe areas. Every token that depends on a themed token MUST have a value in both themes.

**REQ-0002#1**

```gherkin
Given a rendered interactive surface using the primary canvas, surface, foreground, and accent tokens
When reduced-motion preference is active
Then non-essential transitions and loading shimmer animations are suppressed while visual hierarchy and focus indicators remain intact
```

**REQ-0002#2**

```gherkin
Given any component
When its visual values are inspected
Then each comes from a semantic token, with no raw value and no fallback value
```

**REQ-0002#3**

```gherkin
Given any text, status, link or code color in either theme
When it is shown on the canvas or on a surface
Then its contrast is at least 4.5 to 1, and data series reach at least 3 to 1
```

**REQ-0002#4**

```gherkin
Given a light region inside a dark page
When a composite token such as a gradient is used there
Then it resolves to the light colors
```

Because:
- FCT-0002 (active): Lumen establishes a dark-first visual language with ambient glow, hairline borders, and reduced-motion fallbacks
- FCT-0003 (active): Design system ships dark-first default tokens with an explicit light theme preset
- FCT-0008 (active): Lumen-inspired surface and accent tokens maintain accessible contrast across general-purpose application pages
- FCT-0010 (active): The design system uses six tiers with tokens as the first and Pages outside the shared package
- FCT-0011 (active): The token tier offers a complete vocabulary, also where no component uses it yet

### REQ-0003 · Foundational Atoms encapsulate style, expose reactive state, and enforce keyboard accessibility (active)

Foundational Atoms (Button, Text Input, Label, Badge, Icon, Tooltip, and Loading Skeleton) MUST encapsulate their internal presentation, inherit global design tokens, reflect state changes via declared attributes (such as disabled, variant, size, busy, pressed, or a maximum text length), emit standard interaction events, and expose visible keyboard focus rings and accessible roles.

**REQ-0003#1**

```gherkin
Given a Button Atom in a disabled or busy state
When a user attempts keyboard or pointer activation
Then activation is suppressed, the accessible disabled or busy state is exposed, and styling reflects the non-interactive state
```

**REQ-0003#2**

```gherkin
Given a Button Atom that declares a pressed state
When the owning view changes that state
Then the accessible pressed state and styling follow it, and activation alone does not change it
```

**REQ-0003#3**

```gherkin
Given a Text Input Atom with a maximum length
When a user types past that length
Then the extra characters are not accepted
```

**REQ-0003#4**

```gherkin
Given a Tooltip Atom inside a container that clips its content
When the tooltip opens
Then its whole label is visible within the viewport
```

**REQ-0003#5**

```gherkin
Given a Button Atom that controls a menu or panel
When the owning view declares whether that is open
Then assistive technology is told so on the focusable control
```

**REQ-0003#6**

```gherkin
Given Text Input and submit Button Atoms inside a form
When the user activates the Button or presses Enter in the Text Input
Then the form validates and submits once, carrying the named value
```

**REQ-0003#7**

```gherkin
Given Text Input and Button Atoms inside a form
When the form is reset, or its group of controls is disabled
Then the Text Input returns to its declared value, or both Atoms become inactive
```

Because:
- FCT-0001 (active): Atomic Design organizes interfaces into five strictly layered compositional tiers
- FCT-0007 (active): Encapsulated native components styled via shared design tokens scale across foundational tiers without external UI frameworks

### REQ-0006 · Agents working in any repository can consult a structured catalog of tokens, components, and usage rules (active)

The design system MUST expose a structured, agent-consultable catalog organized by the six tiers and covering every available token, Atom, Molecule, Organism, and Template — including its tag or identifier, declared inputs/attributes, content slots, emitted events, accessibility obligations, and compositional examples — so agents building user interfaces in other repositories can query and apply the design system without inspecting internal implementation code. Each tier MUST state its purpose, the tiers it may use and its members, and each component MUST list the components it composes.

**REQ-0006#1**

```gherkin
Given an agent in a separate repository tasked with building a new user interface
When the agent consults the design system catalog
Then the agent can identify the required tokens, component contracts, and composition examples without reading internal component source files
```

**REQ-0006#2**

```gherkin
Given the catalog in any of its forms
When a reader goes through it from top to bottom
Then it follows the tier order from Tokens to Pages, every token and component appears in exactly one tier, and the listed composition matches the implementation
```

**REQ-0006#3**

```gherkin
Given a reader who looks at one component in the live catalog
When they want to know what it is made of or where it is used
Then they can follow links to the lower-tier components it composes and to the components that compose it
```

Because:
- FCT-0005 (active): Cross-repository agents consult the design system via a shared global skill, structured catalog, and zero-build entry point
- FCT-0009 (active): A self-describing design catalog and usage contract enables agents in other repositories to build consistent UIs
- FCT-0010 (active): The design system uses six tiers with tokens as the first and Pages outside the shared package

## Technology Stack

# Technology Stack & Visual Binding

This document binds the technology-agnostic specifications in `.specs/records/` (rendered to `specs/`) to a concrete browser-native implementation and Lumen-inspired dark-first visual language.

Spec-Blueprint: asdlc-meta-specs@latest

## 1. Runtime & Architecture

- **Zero external runtime dependencies:** Plain HTML5, CSS3, and ES2022+ JavaScript. No React, Vue, Tailwind, or bundler required.
- **HTML (Web Components):** Native `<template>`, `<slot>`, `<dialog>`, and Custom Elements (`customElements.define`) using custom tags (e.g., `<ui-button>`, `<ui-input>`, `<ui-media-card>`, `<ui-modal>`, `<ui-navbar>`).
- **CSS (Design Tokens & Shadow DOM):**
  - Global CSS Custom Properties (`--color-*`, `--space-*`, `--radius-*`, `--font-*`, `--shadow-*`) defined at `:root` so tokens pierce Shadow DOM boundaries cleanly.
  - Native CSS nesting and encapsulated Shadow DOM (`attachShadow({ mode: 'open' })`) stylesheets for component-scoped styling.
  - Native `@media (prefers-reduced-motion: reduce)` fallbacks and optical label alignment (`text-box: trim-both cap alphabetic`).
- **Vanilla JavaScript:** Component classes extending `HTMLElement`, using `observedAttributes`, `attributeChangedCallback`, `connectedCallback`, `CustomEvent` dispatching, and ARIA attribute synchronization without a virtual DOM.
- **Verification:** `Spec-Blueprint` (`asdlc-meta-specs@latest`) `check --strict` for specification integrity and native browser / Node test runner checks for component behavior.

| Ambient Glow | Subtle top radial highlights in rose (`rgba(244, 63, 94, 0.08)`) and amber (`rgba(251, 146, 60, 0.05)`) |

| Brand & Status Accents | Rose-crimson primary accent (`#f43f5e` dark / `#e11d48` light), sky info (`#38bdf8`), emerald success (`#10b981`), amber warning (`#f59e0b`) |

## 3. Publishing & Cross-Repository Distribution

- **GitHub Pages Dual-Site Layout (Primary Showcase + Bolted-On Spec Dashboard):**
  - `/` (`site/index.html` & `/showcase/`): Primary live design-system Showcase website demonstrating tokens, Atoms, Molecules, Organisms, and Templates, linking to `./specs/`.
  - `/specs/` (`site/specs/index.html`): ASDLC specification dashboard (records, tasks, graph, capture) fetched dynamically from `asdlc-meta-specs@latest` at deploy time, linking back to `../`.
- **Cross-Repo Agent Consultation:**
  - **Shared Global Skill:** `~/.agents/skills/asdlc-design-system/SKILL.md` points agents in any repository to the design system contract.
  - **Machine-Readable Catalog:** `catalog.json` (plus human/agent `catalog.md`) documents every token, custom element tag, observed attribute, slot, emitted `CustomEvent`, and ARIA contract.
  - **Zero-Build ESM Entry Point:** `src/index.js` registers all custom elements and exports token stylesheets (`https://jvanheerikhuize.github.io/asdlc-meta-designsystem/latest/src/index.js` and `.../latest/src/tokens/tokens.css`, plus `/vX.Y.Z/src/...` for git-tagged releases) so consumer repositories can import components directly without a bundler.
  - **Workspace Version Policy (`TECH_STACK.md` header):** Consumer repositories declare `Design-System: asdlc-meta-designsystem@latest` (default auto-updating channel) or `Design-System: asdlc-meta-designsystem@vX.Y.Z` (pinned release tag). Running `python3 ~/.agents/skills/asdlc-design-system/scripts/sync_consumers.py --apply` aligns every consumer's HTML imports with its declared channel.

## 4. Tier Layout

```text
src/            # Shared package: tiers 1 to 5
├── index.js    # Zero-build ESM entry point registering custom elements
├── tokens/     # 1. tokens.css (--palette-* primitives, then semantic tokens), mkdocs-theme.css
├── atoms/      # 2. One native element each, imports nothing
├── molecules/  # 3. One to three kinds of atom, imports atoms only
├── organisms/  # 4. Imports atoms and molecules
└── templates/  # 5. Slots and CSS Grid, imports nothing
showcase/       # 6. The one page here, a consumer of src/ and catalog.json
```

- **Token rules:** components use `var(--token)` without fallbacks, so `tokens.css` is mandatory. Only semantic tokens may use `--palette-*`. `--anchor-gap` and `--anchor-margin` must be in `px`, because scripts read them.
- **Exceptions:** media and container queries cannot read custom properties, so breakpoints are literals: `640px` (narrow) and `1023px` (drawer becomes modal). `0`, percentages, viewport units, `em`, `fr` and ratios are not tokens.
- **Enforcement:** `tests/test_designsystem.py` checks imports, composition, raw values and unused imports.
